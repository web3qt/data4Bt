# Futures UM 2024-03 To 2025-02 Design

## Goal

Backfill Binance USDT-M futures `1m` data from `2024-03-01` through `2025-02-28` into `data4BT_futures_um`, using the historical symbol universe that existed in that window instead of the current exchangeInfo symbol list.

## Constraints

- The current futures database already starts at `2025-03-01`.
- Existing `run-futures-um-1y` / `watch-futures-um-1y` scripts only cover the current `557` active USDT futures symbols.
- Historical and current backfill tasks must not share state directories.
- The existing month-based `update-latest` flow should remain the actual importer so we do not fork database and scheduler logic.

## Chosen Approach

1. Add a dedicated futures historical backfill workflow for `2024-03` through `2025-02`.
2. Discover historical symbols from Binance's official S3 monthly futures listings, which include active and delisted symbols.
3. For each candidate symbol, inspect its monthly listing and keep it only if it has at least one month inside the target window.
4. Seed a dedicated state directory with `last_date = 2024-02-01T00:00:00Z` and a window-scoped `timelines.json`.
5. Run the existing `./data4bt -cmd=update-latest` importer against the dedicated config.
6. Monitor progress with a dedicated watch script that reads the new state directory and window-scoped timelines.

## Data Flow

1. Query S3 root prefix `data/futures/um/monthly/klines/` and extract all symbol directories.
2. Filter directories to `*USDT`.
3. Query each symbol's monthly `1m` prefix and extract available month files.
4. Keep symbols whose available months intersect `[2024-03, 2025-02]`.
5. Write:
   - `state/futures_um_2024_2025/symbols.txt`
   - `state/futures_um_2024_2025/timelines.json`
   - `state/futures_um_2024_2025/progress.json`
6. Start the existing monthly importer with `scheduler.end_date = 2025-02-28`.

## Monitoring

The dedicated watch script should report:

- Whether the importer process is running
- Historical symbol count discovered for the window
- Expected month count from `timelines.json`
- Not started / in progress / done symbol counts based on `progress.json`
- Database row count inside the target window
- Top progressing symbols

## Risks

- Some historical symbols contain non-ASCII characters, so S3 prefix requests must be URI encoded.
- Some symbols listed in the window may start after `2024-03`; the importer must tolerate missing early months. The current importer already skips `DataNotAvailableError`, so this is acceptable.
- Discovery should be cached in the state directory because it is more expensive than starting the importer.
